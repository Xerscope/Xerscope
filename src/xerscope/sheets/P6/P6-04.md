# P6-04 · Large Durations

Open activities whose remaining duration is above x.

## Population (denominator)
Start: every activity of the file (`TASK` rows; a WBS summary, `TT_WBS`, is never an activity).
1. not complete: `TASK.status_code` is not `TK_Complete` (101248)
2. not level of effort: `TASK.task_type` is not `TT_LOE` (101248)
3. not milestone: `TASK.task_type` is not `TT_Mile` or `TT_FinMile` (46282)

## Counted (numerator)
`TASK.remain_drtn_hr_cnt` > `limit_hours`.

The comparison is in hours, as P6 stores durations. x = `limit_hours = 352` in `p6.toml`:
44 days of 8 hours, P6's default. On a 10-hour calendar 352 h is 35.2 working days, so a
40-day activity on that calendar is counted.

Value = counted / population × 100. Target `< 5%`.

## Source
- [P6 EPPM help, Check Schedule dialog defaults (91574)](https://docs.oracle.com/cd/G18294_01/p6help/en/91574.htm):
  default 352 h, target less than 5 %.
- [P6 Professional help (101248)](https://docs.oracle.com/cd/G18296_01/client_help/en_US/101248.htm):
  completed, WBS summary and level of effort activities are not included.
- [P6 EPPM help, Large Durations section (46282)](https://docs.oracle.com/cd/G18294_01/p6help/en/46282.htm)
  also removes milestones; the [Ten Six r22.12 report](https://tensix.com/using-the-p6-check-schedule-tool/)
  shows P6 Professional doing the same.
- [P6 Professional help, Dates and Durations tab (113175)](https://docs.oracle.com/cd/G48902_01/client_help/en_US/113175.htm):
  the limit is the value set in the dialog.

## Example
| Activity | Calendar | `remain_drtn_hr_cnt` | Result |
|---|---|---|---|
| A100 | 8 h/day | 353 | counted |
| A110 | 8 h/day | 352 | checked, not counted (not above x) |
| A120 | 10 h/day | 400 | counted (40 d, but 400 h > 352 h) |
| M900 | – | 0 | out of population (milestone) |

2 counted / 3 checked = 66.7 %.

## Change it
x: `params = { limit_hours = 352 }` of `P6-04` in `standards/p6.toml`, in hours. Set it to
the value of your Check Schedule dialog converted to hours. Target: `target`.
