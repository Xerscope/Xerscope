# P6-02 · Hard Constraints

Open tasks whose constraint stops P6 from moving them with the logic.

## Population (denominator)
Start: every task of the file (`TASK` rows; a WBS summary, `TT_WBS`, is never a task).
1. not complete: `TASK.status_code` is not `TK_Complete` (101248)
2. not level of effort: `TASK.task_type` is not `TT_LOE` (101248)

Milestones stay in.

## Counted (numerator)
Primary constraint `TASK.cstr_type` or secondary `TASK.cstr_type2` is one of:

| XER code | P6 name |
|---|---|
| `CS_MANDSTART` | Mandatory Start |
| `CS_MSO` | Start On |
| `CS_MANDFIN` | Mandatory Finish |
| `CS_MEO` | Finish On |

A start constraint (`CS_MSO`, `CS_MSOA`, `CS_MSOB`, `CS_MANDSTART`) on a started task is
not counted: once the task has an actual start it no longer holds anything.

Value = counted / population × 100. Target `< 1%`.

## Source
- [P6 Professional help, Constraints tab (113176)](https://docs.oracle.com/cd/G48902_01/client_help/en_US/113176.htm)
  and [101248](https://docs.oracle.com/cd/G18296_01/client_help/en_US/101248.htm): the four hard
  types above; completed, WBS summary and level of effort tasks, and start constraints on
  started tasks, are not included.
- P6 EPPM counts only Mandatory Start and Mandatory Finish as hard: the sets differ between
  the two products. DCMA-05 uses yet another set (see DCMA-05).

## Example
| Task | Status | `cstr_type` | Result |
|---|---|---|---|
| A100 | In progress | `CS_MSO` | checked, not counted (started) |
| A110 | Not started | `CS_MEO` | counted |
| A120 | Not started | `CS_MSOA` | checked, not counted (soft, see P6-03) |
| A130 | Not started | – | checked, not counted |

1 counted / 4 checked = 25.0 %.

## Change it
Target only: `target` of `P6-02` in `standards/p6.toml`. Another set of constraint types: the
rule `constraints` with `types = [...]` in your own standard.
