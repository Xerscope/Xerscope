# P6-10 · Invalid progress dates

Dates on the wrong side of the data date.

## Population (denominator)
Start: every activity of the file (`TASK` rows; a WBS summary, `TT_WBS`, is never an activity).
1. not level of effort: `TASK.task_type` is not `TT_LOE` (101248)
2. not completed before the data date: not `TASK.act_end_date` < data date (101248)

Data date = `PROJECT.last_recalc_date`. A completed activity whose actual finish is on or after the data date stays in.

## Counted (numerator)
- Not started or in progress: forecast start before the data date. Forecast start =
  `TASK.restart_date` (remaining early start), else `TASK.early_start_date`.
- Any activity: `TASK.act_start_date` or `TASK.act_end_date` after the data date.

Column `reason`: forecast before data date / actual after data date / both. An activity
exactly on the data date is not invalid: the data date is the first instant of remaining work.

Value = counted / population × 100. Target `< 1%`.

## Source
- [P6 Professional help (101248)](https://docs.oracle.com/cd/G18296_01/client_help/en_US/101248.htm):
  not started, start before the data date; in progress, remaining early start before it or
  actual start after it; completed, actual finish after it. Completed before the data date,
  WBS summary and level of effort not included.
- [P6 EPPM help, Invalid Progress Dates section (46281)](https://docs.oracle.com/cd/G18294_01/p6help/en/46281.htm):
  same removals.

## Example
Data date 2026-03-09 08:00.

| Activity | Status | Date read | Result |
|---|---|---|---|
| A100 | Complete | `act_end_date` 2026-03-02 | out of population |
| A110 | Not started | `restart_date` 2026-03-05 | counted (forecast) |
| A120 | In progress | `act_start_date` 2026-03-10 | counted (actual) |
| A130 | Not started | `restart_date` 2026-03-09 08:00 | checked, not counted |

2 counted / 3 checked = 66.7 %.
