# P6-10a · Invalid progress before data date

Incomplete activities scheduled before the data date.

## Population (denominator)
Start: every activity of the file (`TASK` rows; a WBS summary, `TT_WBS`, is never an activity).
1. not level of effort: `TASK.task_type` is not `TT_LOE` (101248)
2. not completed before the data date: not `TASK.act_end_date` < data date (101248)

Data date = `PROJECT.last_recalc_date`. A completed activity whose actual finish is on or after the data date stays in.
The population is the one of P6-10b: P6 reports the two halves of Invalid Progress Dates on two lines.

## Counted (numerator)
- Not started or in progress: forecast start before the data date. Forecast start =
  `TASK.restart_date` (remaining early start), else `TASK.early_start_date`.

Column `reason`: forecast before data date. An activity exactly on the data date is not invalid:
the data date is the first instant of remaining work.

Value = counted / population × 100. Target `< 1%`.

## Source
- [P6 Professional help (101248)](https://docs.oracle.com/cd/G18296_01/client_help/en_US/101248.htm):
  not started, start before the data date; in progress, remaining early start before it.
  Completed before the data date, WBS summary and level of effort not included.
- [P6 EPPM help, Invalid Progress Dates section (46281)](https://docs.oracle.com/cd/G18294_01/p6help/en/46281.htm):
  same removals.
- P6 Professional 26.8 report on the synthetic project CHECKSCHED (`tests/test_p6_checksched.py`):
  "Invalid Progress Before Data Date", a line of its own with its own target.

## Example
Data date 2026-03-09 08:00.

| Activity | Status | Date read | Result |
|---|---|---|---|
| A100 | Complete | `act_end_date` 2026-03-02 | out of population |
| A110 | Not started | `restart_date` 2026-03-05 | counted |
| A120 | In progress | `restart_date` 2026-03-09 08:00 | checked, not counted |
| A130 | Not started | `restart_date` 2026-03-12 | checked, not counted |

1 counted / 3 checked = 33.3 %.
