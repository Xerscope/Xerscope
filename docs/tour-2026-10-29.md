# Tour of the repository, 2026-10-29 (evening)

State reviewed: `main` at `9de02d9` (remote-access stack, PRs #2–#12) plus branch
`review-2026-10-29` (CPM against the P6 23.12 corpus, `verify/` package). Four passes:
CPM / model / tests (by hand), app / UI / viz, rules / standards / EV, deploy / CI
(three independent reviewers reading the code; every severity-1 item below was
reproduced on a fixture or checked in the source before being listed). Severity:
**1** wrong number, crash or security hole; **2** misleading, unverified or fragile;
**3** design, performance, hygiene.

## Verdict in five lines

1. The **CPM is the strong part**: an evidence hierarchy (P6 corpus > real exports >
   MPXJ), 99.5 % identical to P6 on task-dependent work, one pinned witness per rule.
   Its weak flank is resource-dependent work (62 %) and two rules measured without
   being understood (R3 Progress Override + FF/SF, R6 free float).
2. The **checks (P6 / DECM / DCMA) have no external oracle**: populations and
   thresholds are one person's reading of page ids; six places give wrong numbers today
   (C1–C6 below), none of them caught by a test because the tests encode the same reading.
3. The **app is a set of scripts**: no view-model layer, two caches with stale keys (EV
   under the planned-dates baseline, WBS selection, re-uploaded files), and several
   crash paths on real-world files (no data date, bad baseline, empty finish).
4. The **remote stack is sound in its principles** (userspace Tailscale, loopback,
   bcrypt, distroless, pinned actions) but has one real hole: anything on the tailnet
   reaches Streamlit and Caddy's admin API behind the basic auth, unless the ACL blocks it.
5. CI runs no linter, refetches third-party corpora in eight jobs, builds no image on
   pull requests and never runs a container.
